AI-200 Study Hub

Full-Stack Web AppLive · private

A private study hub I built to prepare for Microsoft’s AI-200 (Azure AI cloud developer) exam — a schedule, practice, flashcards and hands-on labs in one place, with progress that tells the truth.

I wanted to study for AI-200 the way I build software: with a plan, a feedback loop and no hidden costs. The hub turns the official exam objectives into 65 dated sessions across a 13-week plan, links each one to free Microsoft Learn content, and tracks what I actually complete. The exam date is stored as a tentative target, not a booked appointment.

It deliberately works without any paid service: the app calls no AI model, never provisions Azure resources, and keeps all practice content original. Labs are local-first, and anything that could incur Azure charges is labelled and left for me to run by hand.

Features

  • Today — the next session with one-click access to its learning path, Mark complete / Needs review / Skip, a weekly throughput ring, and a coming-up list.
  • Learn — the four official AI-200 domains (containers, data services, integrations, secure/monitor/troubleshoot) mapped to weekly sessions and free Microsoft Learn paths.
  • Calendar — week and month views, colour-coded by domain, with scheduled minutes.
  • Practice — original multiple-choice and scenario questions across the four domains.
  • Flashcards — original starter cards with Again / Good / Easy ratings that set the next review date.
  • Labs — 13 weekly hands-on labs, from containerizing an API to tracing a multi-step request, each with a checklist, status, evidence link and notes.
  • Progress — sessions done, time invested, labs complete, cards due, and per-domain accuracy from the last 10 answered questions.

Design decisions

  • Honest progress. Every number comes from real activity. Accuracy uses the last 10 answered items per domain, shows its sample size, and is explicitly not a pass-probability.
  • No surprise cloud bills. The app never provisions Azure. Labs are tagged local/free or “Azure may cost” and the latter are checklists only.
  • Original content only. Questions and cards are written from the objectives and link to official docs — no exam dumps, no scraped Microsoft content.
  • Cost-aware AI. An AI tutor and RAG over Microsoft docs were scoped out of the first release on purpose; they need their own budget, consent and trust review.

Difficulties and how I solved them

1. Keeping the curriculum separate from my progress

Problem. The hub has two very different kinds of data: a curriculum, question bank and card deck that I update as the exam objectives change, and my own progress, attempts and review dates. Mixing them would mean a content update could overwrite my history — or a writable “questions” collection could be tampered with.

Solution. I split them. The 65 dated sessions, questions and starter cards ship as versioned, read-only content with stable IDs. Personal state — session progress, quiz attempts, card reviews, lab notes — lives in Firestore under my user ID and refers back to content by those IDs. Security rules deny everything by default and allow only the owner, so a content release never touches my history.

2. Getting a single-page app deployed cleanly

Problem. A single-page app with sign-in behaves differently once it leaves localhost: deep links such as /labs must still load on refresh, and Firebase Authentication only works from domains it has been told to trust.

Solution. I deployed to classic Firebase Hosting rather than App Hosting — a static bundle with no server to maintain and no billing-enabled products — with single-page-app rewrites so deep links resolve. I added the hosted domain to Authentication’s authorized domains, deployed the security rules before entering real data, and verified the production site over HTTPS, signed in and out, rather than trusting the local build.

What building it taught me

Cloud

  • Studying for AI-200 meant working through the platform end to end — containers and Container Apps, Cosmos DB and PostgreSQL with vector search, Redis, Functions, Service Bus and Event Grid, Key Vault, and OpenTelemetry — and turning each into a hands-on lab.
  • Shipped the hub itself on Firebase: Authentication, Cloud Firestore for per-user progress, and Firebase Hosting.

AI-assisted engineering

  • Wrote the build as a phased spec with merge gates and agent guardrails — one phase per pull request, tests before merge, and no paid model APIs or cloud upgrades without approval.
  • Kept humans in charge of content: the AI helped build the app, while the questions, explanations and curriculum choices stayed reviewable and source-linked.

System design

  • Separated read-only canonical content (the curriculum, question bank and starter cards) from private per-user state such as session progress, attempts and review dates.
  • Designed the spaced-review scheduler as deterministic, testable pure functions rather than an opaque algorithm.
